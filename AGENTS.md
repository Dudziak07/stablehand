# stablehand

This repo is a workshop: people open it to build skills and agents **for other repositories**. It has no application code.

## Using this repo (read first)
When the user asks for a skill, an agent, instructions or a whole agent setup **for a repository**, for example "I need a skill for ../shop-api that runs our migrations":
1. Establish the **target repo path** and the **target platform** (Claude Code, Antigravity or OpenCode; default: the tool you are running in). Ask if either is unclear.
2. Load the matching stablehand skill:
   - a whole setup, or "what does repo X need" → `designing-agent-setups`
   - one skill → `authoring-skills`
   - one agent → `authoring-agents`
   - AGENTS.md / CLAUDE.md / rules → `writing-project-instructions`
   - an existing artifact for another platform → `porting-artifacts`
   - testing → `evaluating-artifacts`; format checks → `validating-artifacts`
3. Artifacts are written into the **target repo**, never into this repository.

If the stablehand skills are not available in your tool, wire this checkout first, then reload or reopen the folder:
`uv run tools/install.py <claude-code|antigravity|opencode> --scope workspace`

## Contributing to stablehand itself

### Commands
- Refresh generated copies: `uv run tools/sync.py`. CI checks this with `--check`.
- Lint a platform implementation: `uv run tools/lint.py --platform <claude-code|antigravity|opencode> platforms/<p>`
- Linter tests: `uv run --with pytest --with pyyaml pytest tools/tests -q`
- Validate the Claude plugin: `claude plugin validate .`
- Claude evals: `claude plugin eval platforms/claude-code --allow-tools Write Edit --scaffold` (`--scaffold` builds the `external-target-repo` fixture; read its `setup.sh` first). Runs cost usage.

### Where to edit
- Behavior: `contracts/` first; set its `version` to the next release (`YYYY.M.N`, see `contracts/README.md`) and bump the plugin manifests to match. Then update every implementation under `platforms/` and its row in `platforms/README.md`.
- Platform knowledge and guides: `shared/references/`. Never edit files that start with `GENERATED by tools/sync.py`.
- Validator: `tools/lint.py`. Each new check needs a test in `tools/tests/test_lint.py`.
- Scenarios: `evals/scenarios/`. Update every platform's translation in the same change.

### Boundaries
- Every platform fact in `shared/references/` carries a source in the card header or inline. Update "Last verified" when you re-check.
- Write all text yourself. Credit ideas in `docs/sources.md`. Never paste third-party text without its license notice.
- Keep repo text in English. Every frontmatter string in skills and agents is double-quoted.
- Python tools are uv scripts with inline PEP 723 dependencies; there is no `requirements.txt` or `pip`.
- Commits follow Conventional Commits.
